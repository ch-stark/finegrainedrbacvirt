# Full Admin Fleet Virtualization RBAC Example

PolicyGenerator-based deployment of a custom **full admin** role for ACM Fleet Virtualization, layered with the built-in CNV and ACM extension roles.

## Role stack

| Layer | Role | Where |
| --- | --- | --- |
| Console access | `acm-vm-fleet:admin` | Hub (ClusterRoleBinding, see below) |
| Custom VM ops | `custom-vm-full-admin-role` | Hub + managed clusters |
| CNV base | `kubevirt.io:admin` | Managed clusters (via MRA) |
| ACM extended | `acm-vm-extended:admin` | Managed clusters (via MRA) |
| Migration checks | `acm-vm-cluster-migration:view` | Managed clusters (via MRA) |

## Prerequisites

- ACM 2.16+ with fine-grained RBAC enabled (`fine-grained-rbac` component on MultiClusterHub)
- OpenShift Virtualization on hub and target managed clusters
- Identical identities (users/groups) across hub and spokes
- A Placement resource named `all-clusters` in `open-cluster-management-global-set` (or edit the MRA manifest)
- PolicyGenerator kustomize plugin available in your GitOps pipeline

## Deploy

```bash
# GitOps / kustomize with PolicyGenerator plugin
kubectl apply -k examplefulladmin/

# Hub console prerequisite (create separately — not generated by PolicyGenerator)
oc create clusterrolebinding virt-full-admins-fleet-admin \
  --clusterrole=acm-vm-fleet:admin \
  --group=virt-full-admins
```

## Customize

- Replace `virt-full-admins` group in `hub-manifests/02-hub-mra-full-admin.yaml`
- Update placement name/namespace to match your cluster selection
- Adjust `policies` namespace in `policy-generator.yaml` if needed

## Optional roles

Six additional OpenShift Virtualization roles (execution, admin-without-delete, snapshot,
migration, storage, console) are available under `hub-manifests/optional/` and
`spoke-manifests/optional/`. They are **not** included in the default PolicyGenerator
config — apply or wire them in manually. See [optional-roles.md](optional-roles.md).
